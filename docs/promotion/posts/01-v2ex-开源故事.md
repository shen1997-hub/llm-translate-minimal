# V2EX 分享创造帖（选题 6）

> 发布节点：分享创造。GIF 发布时传图床后替换，此处保留 raw 链接作底稿。

标题：我开源了一个极简 LLM 网页翻译扩展，选中翻译时会有只猫探出头

## 正文

先说动机。我一直在用沉浸式翻译这类工具，体验确实不错，但用着用着总被订阅和额度卡住：免费额度翻几页就见底，想用顺手的模型得开订阅。可我手里明明已经有 DeepSeek 和 GLM 的 key，硅基流动上目前甚至还有免费模型。我就想不通一件事：翻译网页，为什么要再交一份订阅钱？

想不通，就自己写了一个。原则只有一条：不做全家桶，把「整页双语对照」和「划词翻译」两件事做扎实，key 用你自己的，每一分 token 钱花在哪自己说了算。

功能照实列，不夸大：

- 整页双语对照：智能识别正文区域，导航栏和侧边栏不翻，译文插在原段落下面
- 划词翻译：选中文本出现小圆钮（开了猫就是猫），点击弹浮窗；支持朗读、复制、失败重试、图钉固定
- 猫咪助手：选中文字时猫会跳到选区尾巴上探出头，平时停靠在屏幕边缘，可拖拽，不想看到它可以在设置里关掉
- 多供应商：任意 OpenAI 兼容 API——DeepSeek、智谱 GLM、OpenAI、Moonshot、本地 Ollama 都行，Claude 的协议也支持
- 本地缓存：IndexedDB 按「文本+模型+目标语言」分键缓存，重复浏览同一页面不重复计费
- 并发限流 + 429 自动退避；popup 里翻译前会预估段落数和 token 数，心里有数再按
- 12 种目标语言；划词内容 CJK 占比过半自动译成英文，不用手动切方向
- 站点黑名单：popup 一键停用当前站点

差异化就两点，不贬低同行：

1. 没有自己的服务器。API key 只存在浏览器本地（chrome.storage.local），请求只发给你配置的那个供应商域名，每一行网络请求的代码都在仓库里，欢迎翻。
2. 功能少是故意的。不做 PDF、不做 epub、不做视频字幕。需要全家桶的请继续用沉浸式翻译，那是好产品；这个项目服务的是「只想安安静静翻个网页」的场景。

安装目前是源码构建，三条命令：

```bash
git clone https://github.com/shen1997-hub/llm-translate-minimal.git
cd llm-translate-minimal
npm install && npm run build
```

然后打开 chrome://extensions → 开「开发者模式」→「加载已解压的扩展程序」→ 选 `.output/chrome-mv3`。Firefox 用 `npx wxt build -b firefox`，需要 127+。

仓库地址：https://github.com/shen1997-hub/llm-translate-minimal

技术栈一句：TypeScript + WXT（Manifest V3），运行时依赖只有两个（idb-keyval + sql.js），MIT 协议。觉得有用欢迎 star，踩到坑欢迎 issue，都会回。

## 置顶回复预案

**Q：和沉浸式翻译比？**
A：轻量 + 自带 key + 目前有免费模型可用，功能少但够用；需要全文润色、双语 epub 的请继续用沉浸式。

**Q：Firefox？**
A：支持，`npx wxt build -b firefox`，需 Firefox 127+。

**Q：为什么不上架商店？**
A：在排期，当前先源码构建，三条命令就能跑，代码可以先审再用。
