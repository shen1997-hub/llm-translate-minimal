# 大模型网页对照翻译插件 — 设计文档

日期：2026-09-18
状态：待用户审阅

## 目标

开发一个浏览器插件，将网页上的英文内容翻译为中文，以「全文对照」方式呈现（原文段落下方显示译文）。翻译引擎使用大模型 API（OpenAI 兼容协议），用户填写自己的 API Key。

## 技术选型

- 框架：WXT（TypeScript，Manifest V3，一套代码打包 Chrome / Firefox）
- 翻译协议：OpenAI 兼容的 `/chat/completions`，用户可配置 base URL / API Key / 模型名，支持 DeepSeek、Kimi、OpenAI 等任意兼容厂商
- 测试：Vitest（WXT 自带集成）

## 整体架构

```
┌─────────────────────────────────────────────┐
│ Popup（点击图标）                              │
│  开关当前页翻译 / 显示状态                       │
└──────────────┬───────────────────────────────┘
               │ 发消息
┌──────────────▼───────────────────────────────┐
│ Content Script（注入网页）                      │
│  段落提取器 → 找出正文里的英文段落                │
│  译文渲染器 → 在段落下方插入译文块                │
│  （只负责 DOM，不直接调 API）                    │
└──────────────┬───────────────────────────────┘
               │ 消息传递（段落文本）
┌──────────────▼───────────────────────────────┐
│ Background Service Worker                     │
│  翻译调度器：分块 → 并发限流 → 调 LLM API        │
│  缓存：chrome.storage，key = 原文 hash           │
└──────────────┬───────────────────────────────┘
               │ OpenAI 兼容 HTTP 请求
        DeepSeek / Kimi / OpenAI …
```

关键决策：API 调用放在 background service worker 而非 content script，原因：

1. 避免网页 CSP 拦截请求
2. API Key 不暴露在页面上下文中

## 核心组件

### 1. 段落提取器（content script）

- 用选择器遍历 `<p>`、`<li>`、`<h1>`–`<h3>`、`<blockquote>` 等块级元素
- 过滤规则：纯空白、长度 < 20 字符、已含大量中文的段落跳过；`<pre>` / `<code>` 代码块默认不翻
- 用 WeakSet 标记已处理节点；SPA 页面用 MutationObserver 监听新增内容
- 只提取 `innerText` 送翻译，译文单独插入段落下方，不改动原 DOM 结构（避免破坏网页布局与事件）

### 2. 翻译调度器（background）

- 段落去重：hash 缓存命中直接返回
- 批量策略：多个短段落拼进一次请求（带编号分隔），减少请求数、节省 token
- 并发限流：最多 3 个并发请求；429 / 5xx 指数退避重试
- 流式响应：译文逐组到达即渲染，长页面无需等待全部完成

### 3. 译文渲染器（content script）

- 每个段落下方插入 `<div class="llm-translation">`，浅色左边框区分原文
- 翻译中的段落显示占位 spinner；失败显示「重试」按钮

### 4. 设置页（options page）

- base URL、API Key、模型名、系统提示词（可自定义翻译风格）
- 网站黑名单（不注入的域名）、目标语言（默认中文）

## 数据流

1. 用户点 popup 的「翻译本页」→ popup 向当前 tab 的 content script 发消息
2. 提取器收集待翻段落（跳过已处理的），批量发给 background
3. background 查缓存 → 未命中的按批量策略分组 → 并发调 LLM
4. 每组结果返回后立即发回 content script 渲染对应段落（不等全部完成）
5. 结果写入 `chrome.storage.local` 缓存，容量将满时按 LRU 清理

## 错误处理

- 网络 / 限流失败：单组重试最多 3 次（退避 1s / 2s / 4s），仍失败则该组段落标记失败，其余不受影响
- API Key 无效（401）：停止本次翻译，popup 显示明确提示并引导跳转设置页
- 返回格式异常（模型未按编号返回）：该组降级为逐段单独请求，再失败则标错
- SPA 路由切换：自动清理旧译文标记，用户可重新触发

## 测试方案

### 单元测试（Vitest）

- 段落提取器：jsdom 构造各类 HTML 片段，验证过滤规则（短文本 / 中文 / 代码块）与 SPA 增量提取
- 批量分组与编号解析：验证拼接策略、模型返回格式异常的降级逻辑
- 缓存：hash 命中、LRU 清理

### 手动验收

- 真实页面：Wikipedia、技术博客（Medium / dev.to）、SPA（GitHub / X）
- 验证点：译文位置正确、不破坏原页面交互、动态加载内容可翻、失败段落可重试
- 用真实 API Key 跑完整流程，确认流式渲染与缓存生效

## 明确不做（YAGNI）

- 划词 / 悬停翻译
- 内置免费翻译源（谷歌 / 微软网页接口）
- PDF 翻译
- 译文替换原文的「沉浸模式」切换（仅对照模式）
